# GUI smoke checklist (maintainer material)

Runs with `npm run smoke:gui -- --port <port>` against a second Obsidian instance with its own profile; one call with `tools/obsidian-cdp/messlauf.sh` in the parent workspace builds, sets up the staging vault, starts the instance, runs the driver and stops the instance (recipe and lock in the header of `scripts/gui-smoke.ts`).
The fixture vault is `fixtures/vault/` and is rebuilt by `npm run smoke:gui -- --setup`.
All values in the fixture are invented (`Person_k3x9m2ab7q`, `Person_k3x9m2ab7q_Mail`).

This is the stand of task 12 part b: setting up, a device file of a foreign device, the tab "Devices and keys", locking by a deleted key, entering the code, setting up anyway over existing files, replacing the key, forgetting a person and removing a device are measured (points E to K, then H, X, Z, D).
Task 16 adds the revealing in the reading view and copying (points W, U, Y, M, N, O, Q, P and J), run in the bundled run of 2026-11-19 (see Runs).
Task 14 adds the review window (points B1 to B5), run in the bundled run of 2026-11-19: an interactive `transform` opens it, the ways, cancelling with the button and with the real Escape key, applying, marking more places in the text, and two pictures (desktop and 402 px wide).
The picture at 402 px is a reconstruction: the driver cannot switch `Platform.isPhone`, so it sets the body classes `is-phone` and `is-mobile` and the modal class `pseu-review-full` itself and sets the window width; it is not a real phone (the phone measurement stays with Johannes).
The pictures go to a throw-away folder under the system temp directory, whose path the driver prints; they are to be looked at by the session that runs the driver.
Task 15 adds the commands "Pseudonymize selection" and "Pseudonymize this note" (points NA1 to NA7), run in the bundled run of 2026-11-19: the driver creates invented notes with the prefix `Smoke-` in the fixture vault (the fixture itself is never changed), runs the commands by id, answers the dialogs with real clicks and deletes the notes again, also in the cleanup.
Task 17 adds the revealing in Live Preview (points LP1 to LP8), run in the bundled run of 2026-11-19: the driver creates invented notes with the prefix `Smoke-` (`Smoke-LP.md`, and for LP7 a note of 10 000 lines with 500 placeholders and a control note of the same size without any, both created and deleted by the driver), opens them in Live Preview, reads the widgets of the editor (`.okit-swap-inline`) and fires real `copy` and `cut` events with their own clipboard at the editor (the system clipboard stays untouched).
Berta Beispiel is known to the table at that point (name only), her address is not, so the review window opens for the address.
NA3 counts the `modify` events of the note (exactly one write, the single `swapNote`); NA4 compares the properties pane with the file character by character.
The undo in NA1 and NA2 uses the editor's own `undo()`; the file history (Obsidian Sync or File recovery) is not driven.
Task 18 adds the tabs "Persons" and "Exceptions" (points AP1 to AP7), run in the bundled run of 2026-11-19.
The driver writes a second foreign device file (`smoke-fremd2.pseudo`, device "iPad (Treiber)") with two invented persons, Anna Probe (mail `anna@example.org`, phone `030 5550101`) and Anton Probe, works in the tabs with real input (`Input.insertText`) and real clicks, and deletes the file again after AP5 so that point D finds the device list as before.
AP1 to AP5 end in a forgotten, merged entry; the file on the disk is opened with the key in the driver and must hold the detached mail but neither name nor the number.
AP6 reads `data.json` of the plugin from disk and must find no part of the exception text in it.
The pictures of AP7 go to a throw-away folder under the system temp directory, whose path the driver prints; the tap-target heights at 402 px come from a reconstruction (body class `is-mobile` and window width), not a real phone.
A write error in the tabs (the notice "The device file could not be written") is covered by the unit tests; the driver does not make the disk read-only.
Points E to D change the state in this order (not set up, ready, locked, ready, locked, ready on a new chain, ready on a second chain, reading and copying, a person forgotten, the forgetting seen in the open reading view, a device removed); they run once per instance and clean up the key of the throw-away profile in the cleanup.
The reading points use two invented fixture notes (`Lesesicht.md`, `Kopieren.md`) that the driver opens in tabs and popout windows and closes again; it never modifies them (the checksum of the file is part of point U).
The cleanup puts the switch and the copy setting back, restores the clipboard and `showSaveDialog` descriptors, switches the network capture off and closes every leaf the driver opened.
The driver opens the own device file on disk with the key it reads from the plugin, to see whether the forgotten person is still in it (the other person of the same file is the positive control); it never prints a value.

## Counter-probe

`SMOKE_ARGS="--ohne-plugin"` (with `messlauf.sh`) switches the plugin off after the preparation (not saved) and measures every point anyway; every point must turn red, otherwise a point measures something other than the plugin.
The driver switches the plugin back on in its cleanup.
