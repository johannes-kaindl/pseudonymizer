# GUI smoke checklist (maintainer material)

Runs with `npm run smoke:gui -- --port <port>` against a second Obsidian instance with its own profile; one call with `tools/obsidian-cdp/messlauf.sh` in the parent workspace builds, sets up the staging vault, starts the instance, runs the driver and stops the instance (recipe and lock in the header of `scripts/gui-smoke.ts`).
The fixture vault is `fixtures/vault/` and is rebuilt by `npm run smoke:gui -- --setup`.
All values in the fixture are invented (`Person_k3x9m2ab7q`, `Person_k3x9m2ab7q_Mail`).

This is the stand of task 12 part b: setting up, a device file of a foreign device, the tab "Devices and keys", locking by a deleted key, entering the code, setting up anyway over existing files, replacing the key, forgetting a person and removing a device are measured (points E to K, then H, X, Z, D).
`transform` with a table and revealing arrive with the later tasks of the plan; `aria-pressed` on the status bar button is present in the state `ready` and is measured from the revealing task on.
Points E to D change the state in this order (not set up, ready, locked, ready, locked, ready on a new chain, ready on a second chain, a person forgotten, a device removed); they run once per instance and clean up the key of the throw-away profile in the cleanup.
The driver opens the own device file on disk with the key it reads from the plugin, to see whether the forgotten person is still in it (the other person of the same file is the positive control); it never prints a value.

| D | The foreign row has the button "Remove device", this device's row has none; the dialog warns that the file cannot be read and that what only it knew is lost with it; after confirming the foreign file is gone and the own one stays | real clicks, folder read with Node |

## Counter-probe

`SMOKE_ARGS="--ohne-plugin"` (with `messlauf.sh`) switches the plugin off after the preparation (not saved) and measures every point anyway; all sixteen must turn red, otherwise a point measures something other than the plugin.
The driver switches the plugin back on in its cleanup.
